# Find repository knowledge

Read [the project facts](../../../docs/project.md), then search [the index](../../../docs/knowledge/INDEX.md) and the relevant files using the available file/search tools. An empty index or search result is not proof that no requirement exists.

Read complete relevant documents. Check ID, version, status, scope, approval and any replacement. Templates under docs/templates/ are not active requirements. Cite the path, ID and version actually read; report missing project facts and contradictory sources.

The index is generated by the knowledge-writing agent from document titles and paths. It is navigation, not authoritative source content. If it is missing or appears incomplete, search the knowledge files directly and report the drift; do not silently regenerate it during a read-only task. Reading existing knowledge requires no CLI or package manager.

Do not infer implementation from a requirement: inspect code and tests separately when the task needs that evidence.
